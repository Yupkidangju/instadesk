# InstaDesk 2.2.1

## Changes

- Restrict Electron main API gateway paths to `/v1/machines` (rejecting encoded `%2f`/`%5c`/`%00` separators) and validate `machineId`/`profileId` identifiers in `instaboxClient` and preset loading while clamping log `tail` bounds (`1..5000`).
- Prevent duplicate form submissions in `ApiKeyModal` (create, unlock, passphrase change) and re-read the latest vault state in `cryptoVault.unlock()` before updating or clearing failed-attempt counters.
- Harden telemetry, desktop, and sidebar VM controls with `Promise.allSettled` partial-failure isolation, visible error alert banners, stale-response/unmount guards, and per-VM busy locking.
- Clear the VM name input when reopening `CreateVmModal` or after VM creation succeeds, and synchronize 2.2.x build/audit/implementation documentation.

## 변경 사항

- Electron 메인 API 게이트웨이 허용 경로를 `/v1/machines` 범위로 제한(`%2f`/`%5c`/`%00` 차단)하고, `instaboxClient` 및 프리셋 로더의 `machineId`/`profileId` 형식 검증과 로그 `tail` 범위(`1..5000`) 제한을 적용했습니다.
- `ApiKeyModal`의 볼트 생성·잠금 해제·암호 변경 폼 중복 제출을 차단하고, `cryptoVault.unlock()`에서 최신 저장소 상태를 재확인한 뒤 실패 횟수 누적·자동 초기화·성공 시 초기화를 수행하도록 보강했습니다.
- `MetricsLogsView`·`ProcessListView`·`DesktopScreenView`에 부분 실패 격리, 오류 배너, 요청 세대·언마운트 가드를 적용하고 `SidebarVmList` 전원/삭제 제어에 중복 클릭 방지와 오류 배너를 추가했습니다.
- `CreateVmModal` 재오픈 및 생성 성공 시 이름 입력값을 초기화하고 빌드·감사·구현 문서를 동기화했습니다.
